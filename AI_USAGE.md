# AI Usage Report

## Project: Грузовые аукционы (SPA)

### Общая информация

В процессе разработки использовался AI-ассистент (DeepSeek) для ускорения написания кода, генерации типов и решения типовых задач.
---

## Какие части делались с AI

### 1. Генерация типов и интерфейсов

- `IAuction`, `IAuctionFilters`, `IBet` — первичная генерация на основе OpenAPI-схемы
- Типы для Zod-схемы `searchSchema`, `betSchema`

### 2. Настройка MSW

- Создание `AuctionStore` с методами `getAuctions`, `getAuction`, `addBet`
- Генерация начальных мок-данных (12 аукционов)
- Обработчики для эндпоинтов `/auctions/list`, `/auctions/:id`, `/auctions/:id/bets`

### 3. Компоненты UI (первичная генерация)

- `AuctionCard` — карточка аукциона
- `AuctionsList` — список с пагинацией
- `Filters` — форма фильтрации
- `BetForm` — форма ставки с валидацией
- `InfoTab` / `BetsTab` — вкладки детальной страницы

### 4. Хуки и бизнес-логика

- `useAuctionsList` с TanStack Query
- `useAuctionDetail` и `useBets`
- `useBetForm` с мутацией и инвалидацией кеша
- `usePrefetchAuction` для предзагрузки

### 5. Утилиты и конфигурация

- константы

### 6. Документация

- Структура `AI_USAGE.md` (этот файл)
- Рекомендации по проверке

## Какие решения кандидат принял сам

### 1. Архитектура FSD

- Выбор Feature-Sliced Design как основной архитектуры
- Распределение компонентов по слоям:
  - `shared/` — типы, конфиги, API-клиент
  - `entities/` — бизнес-сущности (пока нет)
  - `widgets/` — переиспользуемые UI (`AuctionCard`, `Skeleton`, `EmptyState`)
  - `features/` — бизнес-логика (`AuctionsList`, `BetForm`, `InfoTab`)
  - `pages/` — страницы
  - `app/` — настройка приложения

### 2. Выбор UI-библиотеки

- Material UI v6 вместо других вариантов (Ant Design, Tailwind)

### 3. Управление состоянием

- Генерация `routeTree.gen.ts`
- TanStack Query для серверного состояния
- URL search params для фильтров (вместо localStorage)
- Zustand (планируется) для UI-состояния

### 4. Валидация

- Zod для валидации search params с fallback-значениями
- React Hook Form + Zod для формы ставки

### 5. Навигация

- Простые маршруты без вложенности (`/auctions/:id`, `/bet-form/:id`)
- Передача search params при навигации

### 6. Обработка ошибок

- Типизация ошибок через `ApiError`
- Отображение 422 ошибок в форме

---

## Какие AI-предложения были отклонены

### 1. Вложенные маршруты

- **AI предложил:** использовать вложенные маршруты `auctions/$id/bets`, `auctions/$id/bet-form`
- **Отклонено:** созданы простые маршруты без вложенности для упрощения

### 2. Использование `any` в типах ошибок

- **AI предложил:** использовать `any` для упрощения
- **Отклонено:** создан типизированный `ApiError` интерфейс

### 3. Хранение фильтров в localStorage

- **AI предложил:** дублировать фильтры в localStorage
- **Отклонено:** достаточно URL search params

## Какие места кандидат проверял особенно внимательно

### 1. Типизация (TypeScript)

- `statuses` как массив строк в URL (JSON-сериализация)
- `Omit<SearchParams, 'page' | 'limit'>` для фильтров
- `ApiError` и type guard `isApiError`

### 2. Валидация Zod

- `z.coerce.boolean()` для `is_available` / `is_bidder`
- Трансформация `statuses` из строки в массив
- Дефолтные значения с безопасными fallback

### 3. MSW

- Состояние store при мутациях
- Фильтрация по всем полям
- Обновление `trading.myBet` и `trading.userStatus` после ставки

### 4. Форма ставки

- Учёт `minPrice`, `maxPrice`, `step` в валидации
- Подсказка по шагу ставки с заглушками
- Обработка 422 ошибок от MSW

### 5. Prefetch

- `usePrefetchAuction` с проверкой кеша
- `onMouseEnter` на карточке

### 6. Адаптивность

- `Grid` с `size={{ xs: 12, sm: 6, md: 4 }}`
- Мобильная пагинация

## Какие риски остались

### 1. Производительность

- Отсутствие виртуализации для длинных списков (при 12 моках не критично)
- `TanStack Query` кеширование настроено, но не оптимизировано под большие данные

### 2. Безопасность

- Нет аутентификации (по условиям задания не требуется)
- Нет валидации на клиенте для XSS (MUI и React защищают)

### 3. Тестирование

- Написаны минимальные тесты (чистая логика)
- Некоторые тесты могут быть нестабильны
- Нет E2E тестов

### 4. MSW

- Состояние сбрасывается при перезагрузке (нормально для моков)
- Нет имитации сетевых задержек

### 5. Мобильная адаптация

- Проверена базово, но не на реальных устройствах
- `date` поля могут не работать на старых браузерах
